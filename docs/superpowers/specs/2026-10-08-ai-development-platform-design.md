# AI 开发项目管理平台需求规格

## 1. 概述

### 1.1 背景与目标

用户在开发机上维护多个以目录形式存在的 AI 编码项目，并使用不同的编码 Agent。当前项目目录、Agent 会话及相关 Skill、MCP 和提示词分散在不同工具和配置位置中。本平台旨在提供统一的 Web 管理入口，使用户能够管理项目目录、配置项目可用的 Agent、创建和继续 Agent 会话，并集中管理项目所需资源。

### 1.2 目标运行环境

- 平台部署在开发机上，以后台服务方式运行。
- 首期支持 Linux 与 Windows WSL 环境。
- 用户通过浏览器访问 Web UI；允许局域网访问。
- 每台开发机运行一个平台服务实例。该平台管理多个项目目录，每个项目可运行多个 Agent 实例。
- 采用单用户产品模型和一个共享访问密码；不包含多用户账户和角色系统。

### 1.3 设计原则

1. 使用统一工作台和可插拔 Agent 适配器，将 UI 与 Agent 原生接口隔离。
2. Agent 原生数据仍由 Agent 负责；平台保存项目配置、资源定义、会话索引及原生会话映射等平台数据。
3. 以能力声明处理 Agent 之间的功能差异；不支持的功能应明确显示，不假设所有 Agent 行为一致。
4. 对文件系统和配置文件进行可理解、可确认且尽量可恢复的操作。

## 2. 范围

### 2.1 首期范围

- 平台 Web UI、后台服务、单密码登录及平台配置持久化。
- 项目目录的登记、创建、重命名、移动和删除管理。
- 项目级 Agent 后端配置，首期接入 opencode v2 与 pi。
- 每个项目运行多个 Agent 实例，并在统一工作台中创建、发现、查看和续接会话。
- 统一会话消息交互，包括流式响应、停止运行，以及在 Agent 支持时呈现工具调用和确认流程、模型选择。
- Skill、MCP 与提示词资源的管理和自动配置文件同步。
- Linux 与 WSL 环境下的安全、错误报告和基本恢复行为。

### 2.2 非首期范围

- 多用户身份、角色权限和团队协作。
- 云端托管、远程 Agent 节点或跨机器工作区同步。
- 首期 Agent 列表以外的 Agent 接入。
- 要求不同 Agent 全面具备同等原生能力。
- 在平台中实现 Agent 自身的模型推理、工具执行或完整原生配置管理界面。

## 3. 用户与核心场景

首期用户是开发机所有者。主要场景如下：

1. 用户在浏览器登录平台，添加已有项目目录或在允许的工作区根目录内创建新项目。
2. 用户查看项目，启用该项目可使用的 Agent 后端，并启动一个或多个 Agent 实例。
3. 用户在统一工作台创建新会话，或查看可发现的 Agent 原生会话并尝试续接。
4. 用户通过统一界面发送消息、查看流式响应与运行状态，并按 Agent 能力停止执行、选择模型或处理工具确认。
5. 用户管理 Skill、MCP 和提示词，并将资源配置同步到项目或 Agent 配置文件。
6. 用户移动或删除项目目录，并在高影响操作前核对目标路径及操作后果。

## 4. 系统架构与边界

### 4.1 逻辑组件

- **Web 前端**：提供项目、Agent 实例、会话和资源管理 UI。
- **平台后端**：负责登录校验、统一 API、项目目录操作、平台数据持久化、配置同步、Agent 实例生命周期管理和事件转发。
- **Agent 适配器**：为每种 Agent 实现启动/连接、会话发现与创建、消息交互、事件映射、停止及能力声明。
- **平台存储**：保存平台配置、项目记录、Agent 实例记录、资源定义、会话索引及原生 ID 映射。存储位置与受管项目目录分离。
- **Agent 原生存储与项目文件**：由对应 Agent 或用户持有；平台仅在明确的同步规则下写入受管理的配置内容。

### 4.2 Agent 接入方式

- opencode v2 通过其 API 接入。
- pi 通过受控的命令行进程接入。
- 适配器向平台声明能力，例如流式响应、会话发现/续接、停止、模型选择、工具调用事件及确认交互。
- Agent 能力差异必须反映在 UI 与操作反馈中；对不支持的能力显示不可用或不提供入口。

### 4.3 Agent 后端与实例

- **Agent 后端**表示可用的 Agent 类型及其连接/运行配置，例如 opencode v2 或 pi。
- **Agent 实例**表示某项目中实际启动或连接的一个独立运行单元。
- 一个项目可以启用多个后端，并同时运行多个 Agent 实例，包括相同后端类型的多个实例。
- 平台需独立跟踪各实例的项目关联、工作目录、启动参数、运行状态、会话关联、输出流和停止操作，防止实例之间串流或误操作。

## 5. 功能需求

### 5.1 登录与访问

- 平台支持配置一个共享访问密码，局域网浏览器访问前必须通过认证。
- 密码不得以明文形式存储；认证会话应有有效期。
- 后端 API 必须验证认证状态；应防范未授权请求、CSRF 和暴力尝试。
- 平台不得在日志中记录密码、认证令牌或 MCP 凭据。
- 网络绑定与访问范围应可配置；首期默认允许局域网访问，不要求公网部署能力。

### 5.2 项目与目录管理

- 支持登记已有目录、在授权工作区根目录内创建项目，以及查看和搜索项目列表。
- 支持重命名和移动目录，并同步更新平台的项目路径关联。
- 支持从平台解除项目登记而不删除磁盘内容。
- 支持删除项目目录：优先移入操作系统回收站/废纸篓；若环境无法可靠使用回收站，则在永久删除前明确提示不可恢复并要求再次确认。
- 高影响操作前展示规范化后的来源路径、目标路径和操作后果，并要求用户确认。
- 文件操作范围受配置的授权工作区根目录约束；后端校验真实路径，避免路径穿越或通过符号链接逃逸到未授权位置。
- 移动、重命名或删除时若目录不存在、目标冲突、被占用或操作失败，应保留清晰错误信息；平台记录不得无声地指向错误路径。

### 5.3 项目级 Agent 配置与实例管理

- 用户可为每个项目启用/禁用 opencode v2、pi 等已安装且可用的 Agent 后端。
- 平台应显示 Agent 是否安装、是否可连接、版本/兼容性检查结果及诊断错误（若可获取）。
- 用户可在项目中启动多个 Agent 实例，并查看每个实例的运行、停止、失败等状态。
- 用户可停止指定实例；停止操作不得影响同一项目中的其他实例或会话。
- Agent 进程使用受控参数启动；工作目录限制在已登记项目内。平台应处理异常退出、超时及无法启动等错误。

### 5.4 会话管理与统一工作台

- 平台支持通过适配器创建会话，并将会话关联到项目、Agent 后端和 Agent 实例。
- 平台支持发现可访问的 Agent 原生会话；发现范围和可续接能力由各适配器声明。
- 原生会话不能续接时，平台需说明原因或能力限制，不应将其伪装成可操作会话。
- 工作台至少展示会话消息历史、输入框、发送结果和运行状态；支持流式响应。
- 首期支持停止生成/运行，但具体语义按 Agent 能力实现并清晰展示。
- 当 Agent 支持时，工作台可提供模型选择、工具调用呈现与确认交互；不支持时不展示虚假的统一操作。
- Agent 事件映射为平台统一事件类型，同时允许保留必要的 Agent 专有信息，避免丢失重要诊断内容。
- 会话索引与 Agent 原生会话数据分离；平台不声称自身索引替代 Agent 的原生历史存储。

### 5.5 Skill、MCP 与提示词

- 平台支持管理 Skill、MCP 和提示词定义，并将资源关联到一个或多个项目。
- 提示词支持项目级指令和会话中选用的提示词；Agent 具体加载方式由适配器映射。
- Skill 记录其来源、名称、适用 Agent 与同步目标；实际发现/加载能力按 Agent 支持情况展示。
- MCP 记录服务定义、适用 Agent、启用状态及凭据引用；MCP 凭据以本机明文文件保存在平台私有数据目录，Linux/WSL 文件权限限制为 `0600`。API/UI 不返回凭据明文，日志不得记录凭据。
- 资源修改后按已配置规则自动同步到对应项目或 Agent 配置文件。
- 首次将资源关联到同步目标、或改变同步目标时，用户需明确确认应用；确认后，后续对该资源的修改按规则自动同步。
- 每类资源和 Agent 的同步目标、格式及行为必须明确；UI 应在应用前显示目标位置和变更摘要。
- 平台只自动维护自身创建或明确标记为平台管理的配置内容。
- 目标存在不受平台管理的同名配置或平台管理内容被外部修改时，自动同步应暂停并提示用户选择；不得静默覆盖。
- 同步失败需报告具体资源、目标和原因；平台应尽可能保留同步前备份或原内容，并避免记录敏感值。

## 6. 数据管理

平台至少需要持久化以下数据：

- 运行及登录配置、授权工作区根目录。
- 项目平台 ID、路径、启用的 Agent 后端及项目资源关联。
- Agent 实例记录、运行状态与会话关联。
- 会话索引、Agent 类型及原生会话 ID 映射。
- Skill、MCP、提示词定义、同步目标、同步状态及冲突状态。
- MCP 凭据单独保存在平台私有数据目录的本机明文文件中，不与数据库备份/迁移自动合并；部署者需将凭据文件作为敏感数据处理。

项目内容、Agent 原生会话内容和 Agent 原生配置仍由各自原生位置持有，除非用户明确启用了相应配置同步。平台数据与项目目录分离，以避免移动或删除项目目录时误删平台自身状态。

## 7. 非功能需求

### 7.1 安全

- 所有目录操作执行路径规范化和授权范围校验。
- 进程启动不得将用户输入拼接为不受控 shell 命令；参数应以安全方式传递并校验。
- 管理凭据和会话 Cookie；设置合适的会话有效期及登录尝试限制。
- 防止浏览器跨站请求触发目录、进程和资源修改操作。
- MCP 凭据以明文保存在平台私有数据目录；Linux/WSL 文件权限限制为 `0600`，API/UI 不得回显明文，日志必须脱敏。该方案不防护同一开发机上具有相同用户权限或更高权限的进程，也不防护包含该文件的备份。
- 平台访问密码、会话令牌及其他认证信息不得写入 MCP 凭据文件或日志。

### 7.2 可靠性与可诊断性

- 单个 Agent 的启动失败、崩溃或 API 不可用，不应导致平台整体或其他 Agent 实例不可用。
- UI 应区分排队、运行、停止中、已停止、失败及连接丢失等可识别状态（以适配器能力为准）。
- 移动目录、同步资源或停止实例等操作失败时，应提供可操作错误信息，并避免留下误导性的成功状态。
- 应提供 Agent 安装/连接诊断信息及必要的服务日志。

### 7.3 平台运行

- 同一数据目录首期只支持一个平台后台服务实例；多个项目和多个 Agent 实例是正常使用场景。
- 服务需支持 Linux 和 WSL；具体启动、停止、升级方式在实施计划中确定。
- 局域网访问能力不等同于公网安全承诺；首期不以直接暴露到互联网为目标。

## 8. 验收标准

1. 用户可以通过局域网浏览器登录；未认证请求不能访问管理 API，认证失效后需重新登录。
2. 用户可以登记已有目录、创建项目、重命名和移动目录；平台始终正确显示项目当前路径。
3. 删除项目时可以区分“解除登记”和“删除目录”；优先进入回收站，不支持时执行明确的永久删除确认。
4. 用户可为一个项目配置 opencode v2 和 pi，并在项目中同时运行多个 Agent 实例；每个实例具有独立状态和停止操作。
5. 用户可在统一工作台创建会话、发现适配器支持的原生会话、发送消息并查看流式响应；支持的 Agent 可停止运行。
6. Agent 不支持模型选择或工具确认时，UI 明确不提供相应能力；支持时可通过适配器正常工作。
7. 用户可管理 Skill、MCP 与提示词并自动同步配置；外部同名配置冲突时平台提示用户而不静默覆盖；Linux/WSL 上凭据文件权限为 `0600`，API/UI/日志不暴露凭据明文。
8. Agent 启动失败或异常退出时，平台展示诊断状态，其他项目和 Agent 实例仍可使用。
9. 路径逃逸、未授权目录访问和未认证的修改请求被拒绝；日志不包含登录密码或 MCP 明文凭据。

## 9. 分阶段交付建议

需求整体是一个平台，但可按依赖关系拆为三个实现阶段：

1. **基础平台与项目管理**：后台服务、Web 认证、平台存储、工作区根目录、项目登记/创建/移动/重命名/安全删除。
2. **Agent 与会话工作台**：适配器接口、Agent 安装/连接诊断、项目 Agent 配置、多实例生命周期、统一消息和会话索引；优先完成 opencode v2 与 pi 的最小可用闭环。
3. **资源管理与自动同步**：Skill、MCP、提示词定义，按 Agent 的格式映射和配置同步、冲突检测及安全凭据处理。

每个 Agent 的“原生会话发现与续接”和“工具确认”等能力需在实现前按其实际 API/CLI 能力确认；平台需求要求清晰支持或声明不支持，不要求绕过 Agent 原生限制。

## 10. 待实施阶段确认的细节

以下内容不影响已确认的产品边界，但需要在技术设计和实施计划中具体化：

- Linux/WSL 中平台数据、日志、备份的默认存储位置及迁移策略。
- 工作区根目录如何配置，是否允许多个授权根目录。
- 各 Agent 适配器可用的 API/CLI 版本范围、原生会话发现方式和实际能力矩阵。
- 不同 Agent 的 MCP/Skill/项目提示词文件格式、同步目标及项目级与用户级配置优先级。
- 多 Agent 实例的并发数量限制、资源使用提示与实例清理策略。
- 会话历史在平台中的缓存范围、保留期限及清理规则。
- HTTPS、Cookie 属性和局域网内可信部署的具体配置方式。
- 跨文件系统移动、文件被占用和操作系统回收站集成失败时的详细恢复流程。
