# 平台界面布局重构设计

日期：2026-10-10
状态：待用户审阅
依据：已确认的原型 `/tmp/opencode/prototypes/`（01 项目设置、02 任务对话、03 新建任务）

## 1. 目标与边界

### 1.1 目标

将当前「项目列表页 → 项目 Agent 页 → 会话工作台页」的多页跳转，改为类似 ChatGPT 桌面版 / DeepSeek Harness 的三栏工作界面：

- 左侧按项目组织任务，任务用 Agent 后端标签区分。
- 点击项目，右侧显示项目设置。
- 点击任务，右侧显示对话交互页面。
- 最左侧为大类切换栏，首期只有「项目」，后续可加入纯 Chat 类型。

### 1.2 范围内

- 前端布局、路由和导航的重构（`web/src`）。
- 复用现有 API 与 store，不修改后端接口。
- 现有功能迁移到新布局：项目登记/新建/移动/重命名/解除登记/删除、Agent 后端启停与配置、实例管理、会话创建/续接/消息/停止、授权工作区管理、诊断面板。

### 1.3 范围外

- 后端接口与数据模型变更。
- Skill / MCP / 提示词的管理与同步（属于计划 3，尚未实现）。本设计只在项目设置中预留对应区块的位置，见第 6 节。
- 纯 Chat 大类的功能实现（仅预留入口）。
- 移动端适配。

## 2. 概念映射

| 界面概念 | 现有数据模型 | 说明 |
|---|---|---|
| 大类 | 固定值 `project` | 为后续 `chat` 大类预留，首期仅 `project` 可用 |
| 项目 | `Project` | 目录登记记录 |
| 任务 | `AgentSession`（平台会话索引） | 任务即某项目下的一个 Agent 会话 |
| 任务标签 | `BackendId`（`opencode-v2` / `pi`） | 显示会话所属后端 |
| 任务状态 | `SessionStatus` + 所属实例 `InstanceStatus` | 显示运行中 / 空闲 / 断开等 |

「任务」只是界面叫法，数据仍是会话。新建任务即在某个实例上创建会话，沿用现有 `createProjectSession`。

## 3. 布局

```
┌──────┬──────────────────┬──────────────────────────────────────┐
│ 大类 │ 左侧：项目/任务树 │ 右侧：内容区                          │
│ 56px │ 272px            │ 项目设置 或 任务对话                  │
└──────┴──────────────────┴──────────────────────────────────────┘
```

### 3.1 大类栏（最左）

- 首期仅「项目」按钮可用；「Chat」为禁用的预留按钮。
- 底部设置入口（齿轮）预留，首期可指向授权工作区管理与诊断面板。

### 3.2 左侧树

- 顶部：标题「项目」、`+ 新建 / 登记` 按钮（打开现有的登记/新建对话框）、搜索框（匹配项目名或任务名）。
- 项目节点：可展开/折叠，显示任务数量。点击项目名 → 右侧进入项目设置，并展开该项目的任务。
- 任务节点：显示标题、后端标签（`opencode` 蓝色 / `pi` 黄色）、状态标签（运行中 / 空闲 / 断开）。点击 → 右侧进入对话页。
- 每个项目下有 `+ 新建任务`，打开新建任务视图（原型 03）。
- 选中态：项目或任务至少一个高亮；路由与选中态保持一致。

### 3.3 右侧内容区

- 项目设置（原型 01）：项目基本信息、项目操作（打开任务、移动、解除登记、删除）、Agent 后端启停、资源区（占位，见第 6 节）、危险操作说明。
- 任务对话（原型 02）：顶部为任务元信息与停止/重命名，中部为消息流，底部为输入区。
- 新建任务（原型 03）：选择后端、填写任务信息、会话来源（新建 / 续接）。

## 4. 路由与状态

采用单壳布局，左侧树与大类栏常驻，右侧由子路由决定内容。

| 路由 | 右侧内容 |
|---|---|
| `/login` | 登录页（不带三栏壳） |
| `/projects/:projectId` | 项目设置 |
| `/projects/:projectId/tasks/new` | 新建任务 |
| `/projects/:projectId/tasks/:sessionId` | 任务对话 |
| `/` | 无选中时的空状态（提示选择项目或新建） |
| `/*` | 重定向到 `/` |

路由守卫沿用现有 `requiresAuth` 与 401 处理逻辑。

旧路由 `/projects/:id/agents` 与 `/projects/:id/workbench` 迁移为新路由的重定向，避免旧书签失效。

## 5. 组件划分

- `AppShell.vue`：三栏壳，包含大类栏、左侧树、右侧 `RouterView`。
- `CategoryRail.vue`：大类切换，首期数据来源为静态配置列表。
- `ProjectTree.vue`：项目与任务树，负责展开/折叠、搜索过滤、选中态。数据来自 `listProjects` 与每个项目的 `listProjectSessions`。
- `ProjectSettingsPanel.vue`：项目设置。由 `ProjectAgentsView` 中的后端与实例逻辑拆出，复用 `AgentInstanceList`、`CapabilityControls`、`BackendDiagnostics`。
- `TaskChatPanel.vue`：任务对话。由 `SessionWorkbenchView` 中的消息与输入逻辑拆出，复用 `MessageView`、`sessions` store 的流式逻辑。
- `NewTaskPanel.vue`：新建任务，复用创建会话、续接会话接口。
- `BackendTag.vue`：统一的后端标签组件，供树、对话头部、新建任务共用。
- `ProjectDialog.vue` 与 `WorkspaceRootsDialog.vue`：保留，由 `AppShell` 统一打开。

现有 `ProjectsView.vue`（约 490 行）承担了列表、对话框和登出，拆分后：列表职责进入 `ProjectTree.vue`，对话框职责进入 `AppShell` 的对话框管理，登出进入顶部或设置入口。

## 6. 资源区（占位）

原型 A 中的 Skill / MCP / 提示词区块依赖计划 3 的接口，目前不存在。设计如下：

- 项目设置中保留「资源关联」卡片，显示为「待资源管理功能接入」的占位，并给出说明文字。
- 占位不调用任何资源接口，不展示虚假的状态数据。
- 计划 3 实现后，再替换为真实的资源列表与同步状态。

这样本次重构不依赖未完成的功能，同时保留了原型的位置与信息结构。

## 7. 数据流与状态管理

- 项目列表：沿用 `listProjects`，在 `AppShell` 挂载时加载，项目变更后刷新。
- 任务列表：每个展开的项目加载 `listProjectSessions`，按项目缓存；新建或续接会话后局部刷新该项目。
- 流式消息：沿用 `sessions` store 与 `sessionEventsPath` SSE 逻辑，切换任务时关闭旧流、打开新流，避免串流。
- 实例与后端：沿用 `agents` store。
- 选中任务时，若该任务所属实例已停止，输入区禁用并提示「实例已停止，请在项目设置中启动」，不隐藏历史消息。

## 8. 能力与状态展示

- 后端能力沿用 `Capabilities`：不支持模型选择时，对话页模型选择显示为「不适用」；不支持工具确认时不显示确认入口；不支持续接时新建任务中的续接项置灰并说明原因。
- 不向用户展示虚假的统一操作。
- 错误沿用 `describeApiError` 文案，失败的实例或会话在树中以「断开 / 失败」标签显示。

## 9. 错误处理

- 401：沿用现有全局处理，跳转登录。
- 项目或会话不存在（404）：右侧显示提示与「返回项目」按钮，不崩溃。
- 删除、解除登记、移动等危险操作：沿用现有对话框中的二次确认与路径展示，不做简化。
- 流式连接断开：沿用 `sessions` store 的重连状态，在对话头部显示「重连中」。

## 10. 测试

- 单元 / 组件测试（Vitest）：`ProjectTree` 的展开、选中、搜索；`BackendTag` 的颜色与文案；`TaskChatPanel` 在能力不支持时的置灰逻辑。
- 路由测试：各路由的渲染、旧路由重定向、未登录守卫。
- 端到端（Playwright，沿用 `web/e2e` 结构）：
  - 登录后左侧出现项目与任务；
  - 点击项目 → 右侧为项目设置；
  - 点击任务 → 右侧为对话并可发送消息；
  - 解除登记与删除的二次确认仍然有效；
  - pi 任务的模型选择不可用。
- 回归：现有 `workbench.spec.ts`、`projects.spec.ts`、`security.spec.ts` 需按新路由更新，但断言的安全行为（认证、CSRF、路径校验）不得放宽。

## 11. 实施策略

- 分阶段实施，每阶段保持可运行：
  1. 搭建 `AppShell` 与路由，项目设置与对话页先复用旧组件内容；
  2. 拆分 `ProjectTree`，接通项目与任务数据；
  3. 迁移新建任务与会话续接；
  4. 迁移危险操作对话框与工作区管理；
  5. 删除旧页面、更新 e2e 与旧路由重定向。
- 旧页面在阶段 5 之前保留，便于对比和回退。
